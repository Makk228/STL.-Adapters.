# STL Adapters — проект по разработке библиотеки адаптеров

Библиотека адаптеров для C++23, которая позволяет строить потоковые (pipeline) цепочки обработки данных поверх контейнеров, файлов и потоков ввода‑вывода. Это самостоятельный учебный проект, демонстрирующий подход «порции данных → адаптеры → результат» с оператором `|`, а также идею ленивых вычислений для большинства адаптеров.

Ниже — описание того, как устроена библиотека, какие адаптеры доступны и как её собрать/запустить.

## О проекте

**STL Adapters** — учебная библиотека для построения цепочек обработки данных, похожих на `std::ranges`, но реализованных вручную. Это полноценный проект, в котором аккуратно выделены адаптеры, примеры использования и тесты, чтобы библиотеку было удобно расширять и применять в задачах обработки данных.

Идея: каждый адаптер получает поток данных, преобразует его и передаёт дальше. В результате можно создавать выразительные конвейеры обработки с минимальным количеством вспомогательного кода.

---

## Ключевые возможности

- **Потоковая обработка данных** через оператор `|`.
- **Ленивые вычисления** для большинства адаптеров (данные обрабатываются по мере запроса).
- **Работа с файловой системой** (обход директорий и чтение файлов).
- **Объединение и агрегация данных** по ключу.
- **Преобразование и фильтрация** без создания промежуточных контейнеров.

## Адаптеры

Адаптеры реализованы в каталоге `lib/`. Основные из них:

- **Dir** — поток путей файлов из директории (включая рекурсивный режим).
- **OpenFiles** — открывает файл для каждого пути из входного потока.
- **Split** — разбивает поток на токены по заданным разделителям.
- **Out** — выводит элементы потока в заданный выходной поток.
- **AsDataFlow** — превращает контейнер в поток данных.
- **Transform** — применяет функцию к каждому элементу.
- **Filter** — фильтрует элементы по предикату.
- **Write** — записывает элементы в поток с разделителем.
- **AsVector** — собирает результаты в `std::vector`.
- **Join** — левое объединение двух потоков по ключу (аналог `LEFT JOIN`).
- **KV / JoinResult** — структуры для операций объединения.
- **DropNullopt** — удаляет `std::nullopt` из потока `std::optional<T>`.
- **SplitExpected** — разделяет поток `std::expected` на два конвейера.
- **AggregateByKey** — агрегирует значения по ключу (работает **неленивая**).

> Требование по памяти: для всех адаптеров кроме `AggregateByKey` и `Join` — **O(1)** по памяти.

## Архитектура и поток обработки

Потоки строятся оператором `|` и передают элементы по цепочке:

```
Источник -> Adapter1 -> Adapter2 -> ... -> Агрегатор/Вывод
```

Большинство адаптеров ленивые: данные вычисляются только тогда, когда следующий шаг запрашивает элемент.

## Пример использования

Ниже пример цепочки, которая превращает контейнер строк в поток и пишет элементы в `std::cout` с разделителем:

```cpp
#include <processing.h>
#include <vector>
#include <string>

int main() {
    std::vector<std::string> input = {"1, 2, 3", "hello", "world"};

    auto result = AsDataFlow(input)
        | Write(std::cout, '|');
}
```

Пример из задания (подсчёт частоты слов в .txt-файлах):

```cpp
Dir(argv[1], recursive)
    | Filter([](std::filesystem::path& p){ return p.extension() == ".txt"; })
    | OpenFiles()
    | Split("\n ,.;")
    | Transform(
        [](std::string& token) {
            std::transform(token.begin(), token.end(), token.begin(), [](char c){return std::tolower(c);});
            return token;
        })
    | AggregateByKey(
        0uz,
        [](const std::string&, size_t& count) { ++count; },
        [](const std::string& token) { return token; }
      )
    | Transform([](const std::pair<std::string, size_t>& stat) {
        return std::format("{} - {}", stat.first, stat.second);
      })
    | Out(std::cout);
```

## Сборка и запуск

Требования:
- C++23
- CMake ≥ 3.12

Сборка проекта:

```bash
cmake -S . -B build
cmake --build build
```

Запуск демо-приложения:

```bash
./build/bin/labwork8
```

## Запуск тестов

Проект использует **Google Test** и включает набор unit-тестов.

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build
```
